# charter-7-closure.md

`charter` 아크 페이즈 7의 종료 문서. **원장이 받지 않는 것**을 받는다. 낙착은 원장이 들고 계획
변경의 값은 `docs/arcs.json` 의 `patches` 가 든다.

종료 증거는 커밋 `83e9f39` 이며 CI 실행 `35467636612` 가 그것을 검사했다.

---

## 1. 무엇을 했나

원장을 세우고 그것을 검사하는 설비를 붙였다. 카드 열과 정지점 일곱으로 나누어 집행했고 Claude
Code 호출이 한 번이었다.

| | 산출 |
|---|---|
| 원장 | 246 entry (decisions 190 · deferred 33 · retirements 23 · rejected 0) |
| 검증기 | `scripts/check_wiki.py` · 검사 스물넷 |
| 배선 | `verify.sh` 여섯 단계 · CI 워크플로 |
| 표지 | Lean 선언 열다섯 |
| 커밋 | 열하나 · 10 파일 · 1546행 추가 · 30행 삭제 |

티어는 `policy` 139 · `finding` 44 · `invariant` 7 이고, 이연 서른셋의 트리거는 `artifact` 19 ·
`arc_phase` 6 · `extraction` 3 · `null` 5 다.

## 2. 지시서에 없던 조작 넷

전부 집행이 제시하고 결정 세션이 판정했다. **넷 다 결정 세션이 리포의 상태를 확인하지 않아
생겼다.**

**(1) 커밋 둘을 먼저 세웠다.** 카드와 지시서가 `A` 로 스테이징돼 있었고 `SPEC.md` 수정분이
미커밋이었다. 지시서가 그 상태를 전제로 쓰이지 않았다.

**W-8의 한계가 여기서 드러났다.** `git clone` 은 index 를 가져오지 않으므로 새 클론의 index 는
항상 깨끗하고, **결정 세션은 로컬에 스테이징된 것을 볼 수 없다.** 사전 검사가 파일 내용만 보고
git 상태를 보지 못했다.

**(2) 해소된 미결 다섯을 보정 병합했다.** 첫 병합 뒤에 검사 23을 돌려 유령 하나가 나왔다.
`H-22` 의 `basis` 가 K-10을 지목하는데 원장에 그 항목이 없었다. **구멍은 해소분을 넣고 미결은
살아 있는 것만 넣은 비대칭**이 원인이며, 그것이 「원장은 자기완결이다」에 걸렸다.

**(3) Lean 세 파일의 머리말을 두 번 치환했다.** 첫 치환이 `-- DD:<id>` 를 예시로 들어 검사 13이
그것을 표지로 읽었고 계수가 열다섯에서 열여덟이 됐다. **`CLAUDE.md` §5-5가 근거로 든 「주석 안의
문자열이 코드로 오인되는」 형의 두 번째**다. 3단계가 주석을 제거해 해소한 것이 검사 13에는 듣지
않는다. 표지 자체가 주석이기 때문이다.

**(4) `BUILD_LOG.md` 의 삭제 자리를 채웠다.** 경로 누출을 지우기만 해서 재현 절차에 작업
디렉터리 지정이 없고 트리 도식에 뿌리가 없었다. 「지운다」만 지시하고 대체 문면을 안 주었다.

## 3. 명세의 결손 여섯

집행이 멈추고 제시했으며 결정 세션이 명세를 고쳤다. **검증기를 고쳐 통과시킨 것이 하나도 없다.**

| | 결손 | 처분 |
|---|---|---|
| 1 | 원장 컨테이너의 모양이 어느 문면에도 없었다 | `SPEC.md` §1에 적었다 |
| 2 | 검사 12가 `artifact` 의 실재를 요구해 **발화 조건이 이미 충족된 트리거만 등재 가능**했다 | 형식만 보게 했다 |
| 3 | 검사 23의 계열에 `E` 가 들어 추출 기록 번호를 유령으로 잡았다 (141건) | 계열에서 뺐다 |
| 4 | 검사 23의 유니버스에 폐기 레코드의 `statement` 가 들어 스물둘이 걸렸다 | 폐기 레코드를 통째로 뺐다 |
| 5 | 첫 적재의 `related` 가 전량 비어 열일곱이 걸렸다 | `charter-6` 예외를 뒀다 |
| 6 | 검사 13이 구문 종류를 안 가려 블록 주석의 산문을 표지로 읽었다 | 줄 주석으로 좁혔다 |

**5는 결정 세션의 결손이다.** `SPEC.md` §2.1에 `related` 요건을 쓰고서 대장에서 `related` 를
전량 빈 배열로 두었다. 사전 검사가 그것을 못 잡은 이유는 **그 검사가 「토큰이 `names` 에
실재하는가」만 구현하고 「폐기된 것이면 `related` 에 있는가」를 구현하지 않았기 때문**이다.
조항을 부분만 구현한 필터로 통과를 선언했다.

**6의 처분 순서가 중요하다.** 어긋남은 산문에서 표지 꼴을 뺀 것으로 먼저 해소했고, 좁힘은 그
뒤에 재발 방지로 세웠다. 순서를 그렇게 잡은 것이 「검증기를 고쳐 통과시키는 것」과 갈리는 자리다.

집행이 그 좁힘의 음성 대조를 **양방향으로** 돌렸다. 줄 주석에 없는 id 를 넣으면 실패하고 같은
줄을 블록 안에 넣으면 통과한다. 앞이 좁힘 뒤에도 산 검사임을 들고 뒤가 좁힘이 실제로 좁혔음을
든다. **한 방향만 쟀으면 둘이 갈리지 않았다.**

## 4. 계수가 갈린 자리 넷

| | 결정 세션 | 실측 |
|---|---|---|
| `CLAUDE.md` §14 행 번호 | 388~415 | 391~418 |
| 검사 14의 대상 | 다섯 | 넷 |
| 카드 entry | 241 | 246 (보정 뒤) |
| 지시서의 등가 검증 | `241건` 을 문자열로 박음 | §11 지목으로 교체 |

**첫째는 집행의 것이다.** diff 표시의 행 번호를 산출물에서 다시 재지 않고 옮겼다. 원인을
스스로 진단했고 `CLAUDE.md` §12가 금지하는 형임을 적었다.

**나머지 셋은 결정 세션의 것이다.** 둘째는 기대 문면이 수와 목록을 함께 들었는데 수가 틀렸고,
셋째는 보정으로 낡았으며, 넷째는 재생성으로 안 잡히는 자리에 수가 박혀 있었다.

**§6.7 (3)이 이미 경계한 형이 셋 다다.** 표는 대장에서 뽑아 안 걸렸고 **지시 문면과 기대값은
손으로 써서 걸렸다.**

## 5. 막힌 자리

**`blocking` 트리거가 0건이다.** 아크 이름을 `ref` 로 요구하는데 실질 아크가 아직 없다. R-7이
세운 네 종류 중 셋만 실증됐다.

**`artifact` 발화 여섯을 읽는 쪽이 없다.** 전부 `Glossary/Core.lean` 을 가리키고 그 파일이 이미
있어서 났다. 의도는 「용어집에 그 분할이 **등재된다**」였는데 `ref` 가 파일 경로라 **파일 존재만으로
발화**한다. `artifact` 종류가 파일의 존재만 표현하고 내용을 표현하지 못한다.

**검사 3과 4를 독립으로 실패시킬 입력이 없다.** 둘이 같은 조건을 다른 각도에서 보므로 한쪽만
실패시킬 수 없고, 그러면 §3.10-1의 음성 대조가 그 자리에서 공허해진다.

**`dynamics` 둘과 `observation` 하나의 `layer` 가 닿지 않는다.** 대응 디렉터리가 아직 없어서이며
결함이 아니라 해당 층이 아직 서지 않았다는 사실이다.

## 6. 검사가 못 보는 자리 셋

**(1) 상주 문서의 규율 지목.** 검사 23의 유니버스가 원장 안이라 `docs/` 산문을 보지 않는다.
`SPEC.md` 자신이 폐기된 J-23을 산 근거로 들고 있었고, **그 문서가 스스로 경고한 결함류에 여섯 줄
아래에서 걸렸다.** 최종 검토에서 손으로 걸어 잡았다.

실측하면 `CLAUDE.md` 와 `docs/baseline.md` 는 폐기 지목이 0이고, `BUILD_LOG.md` 에 원장에 없는
토큰이 일곱 있으며, 참고자료 목록 둘이 폐기된 S-1을 든다.

**(2) 표지 누락.** R-6이 모든 정의·정리에 표지를 요구하나 검사 13은 **있는 표지가 해소되는지**만
본다. 새 선언을 세우고 표지를 빠뜨리면 어느 검사도 잡지 않는다.

**(3) 되돌림 결합의 실제 형태.** 지시서 §6-1이 `BUILD_LOG.md` 와 `CLAUDE.md` 의 결합을 예측했고
둘 다 일어났으나, 커밋 단위로 갈려 역순 되돌림이 필요한 상황은 나지 않았다. **예측이 맞았으나
대비한 형태로는 나지 않았다.**

따라 **그 뒤에 원장에 카드를 병합하는 첫 회차**가 받는다. 정본은 `docs/arcs.json` 의 `patches` 다.

신설이라 `charter-7` 만큼 무겁다. **분할을 패치가 받아야 한다.**
